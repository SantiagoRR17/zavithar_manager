**API surprises hit while writing this:**

- **Riverpod 3 removed `AsyncValue.valueOrNull`.** The nullable accessor is now `.value`. Cost two compile errors; noted in [ADR 0002](../adr/0002-riverpod-for-state.md) and lesson 02, because every Riverpod tutorial online still uses the old name.
- **`google_sign_in` 7.x is a different API** from every guide out there: `GoogleSignIn.instance`, `initialize()`, then `authenticate()` — and `authentication` now returns *only* an `idToken`, no access token. Firebase accepts the ID token alone, so this is fine. Verified by reading the installed package source rather than trusting docs.
- No `serverClientId` is needed in Dart on Android — the plugin reads the web OAuth client out of `google-services.json`.

`flutter analyze` is clean apart from the missing `firebase_options.dart`, which step 5 generates.

### 5. Firebase project ✅

Project `zavithar-manager` created, Firestore (**Standard edition**, production mode, `us-east1`) provisioned, Google + Email/Password enabled, `flutterfire configure` run, and the security rules deployed:

```
+ cloud.firestore: rules file firestore.rules compiled successfully

```

Generated: `app/lib/firebase_options.dart` and `app/android/app/google-services.json` (both committed on purpose — [ADR 0008](../adr/0008-committing-firebase-config.md)). FlutterFire also added the `com.google.gms.google-services` Gradle plugin to `app/android/app/build.gradle.kts`.

`google-services.json` contains two `client_type: 3` entries — web OAuth clients. That is what `google_sign_in` needs on Android, and its absence is the cause of the `serverClientId must be provided` error.

**Four things that cost time here, all now in `docs/setup.md`:**

- **`firebase projects:create` failed with a useless message.** `Error: Failed to create project. See firebase-debug.log`. The actual cause was in the log: `Callers must accept Terms of Service` — the Google Cloud ToS had never been accepted on the account. Nothing in the CLI's output hints at that. Lesson: read the debug log rather than guessing.
- **Console login ≠ CLI login.** Being signed into the Firebase console in a browser does nothing for the CLI, which keeps its own credential and must be logged in from the terminal. `firebase login:list` is the check.
- **Firestore now asks Standard vs Enterprise.** Standard is correct — Enterprise is the MongoDB-compatible variant, aimed at server-side apps, and is not what the client SDKs, real-time listeners and Security Rules here are built on.
- **`flutterfire` is a `.bat`,** so Git Bash cannot find it by bare name. Ran it from PowerShell instead.

## `.gitignore` correction

The plan said to add `firebase_options.dart` and `google-services.json` to `.gitignore`. **That was wrong**, and yesterday's `.gitignore` was already right: it has an explicit "NOT ignored, deliberately" section for them. A Firebase API key is an identifier, not a credential — every Android app ships it inside the APK. Access is controlled by security rules, not by hiding the key. Written up properly in [ADR 0008](../adr/0008-committing-firebase-config.md), which that section already referenced.
